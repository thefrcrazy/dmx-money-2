Aucune exception non gérée, violation CSP, réponse HTTP >= 400 ou requête échouée
constatée. Un diagnostic `console.error` attrapé reste présent à l'ouverture sans QR :
« Configuration mobile manquante. Ouvrez le lien depuis le QR code. »
L'écran d'installation fonctionne ; ce diagnostic ne valide pas le parcours appairé.
Ce diagnostic vient du refus explicite d'une configuration absente dans
`pwa/src/services/db.ts:289`, attrapé par `pwa/src/context/BankContext.tsx:394`.

Le bureau établit une connexion WSS sortante, sans DNS individuel ni port entrant.
Les échanges financiers sont chiffrés AES-256-GCM entre les appareils. L'appairage utilise
un QR privé à usage unique et une passkey avec vérification utilisateur.
Le service ne remplace pas le bureau : celui-ci doit rester allumé, connecté et DmxMoney ouvert.

Pour migrer : synchroniser d'abord les saisies en attente de l'ancienne PWA,
installer 2.0.8 sur le bureau, activer le compagnon Internet puis scanner son nouveau QR.
Le changement d'origine exige un nouvel appairage. Ne pas supprimer l'ancien stockage
mobile tant que ses saisies ne sont pas synchronisées.

## Limites

- Les contrôles publics du navigateur portent sur l'écran non appairé ; ils ne valident
  pas Face ID/Touch ID ni une modification sur un téléphone réel en 4G/5G.
- Aucun essai d'installation avec Smart App Control actif, sur un PC arm64 réel,
  sur Catalina réel ou avec un compte iCloud réel n'a été réalisé pendant cette livraison.
- La PWA active contrôle les changements toutes les 2,5 secondes ; iOS peut suspendre
  l'application en arrière-plan. La reprise exige sa réouverture et un bureau disponible.
- Le cache mobile est obfusqué en base64, facilement décodable et environ 33 % plus
  volumineux que le JSON UTF-8. SQLite bureau et sauvegardes restent sans chiffrement
  applicatif au repos.
- Le relais voit les métadonnées réseau. Un opérateur modifiant le JavaScript de la PWA
  pourrait compromettre le client ; aucune URL invisible ni confidentialité absolue n'est promise.
